\# CLAUDE.md — Todo 앱 백엔드 (+DB)



이 파일은 Claude Code가 \*\*이 레포\*\*에서 작업할 때 항상 따르는 기준이다.

지침이 애매하거나 아래 범위를 벗어나는 요청을 받으면, 코드부터 짜지 말고 먼저 사람에게 확인한다.



\---



\## 1. 이 레포가 뭔지

\- 3명이 \*\*3일 안에\*\* 만드는 Todo(할일 관리) 웹앱의 \*\*백엔드 + DB\*\* 레포.

\- 담당: 백엔드 + DB.

\- 이 레포의 책임: \*\*① 회원가입/로그인 ② 사용자별 할일 CRUD API ③ SQLite DB ④ 서버 내부에서 도는 알림 발송 로직\*\*.

\- 프론트엔드(React)는 다른 담당/레포.



\---



\## 2. 절대 범위 (이걸 넘지 마)

"만들 것"만 구현한다. "안 만들 것"은 요청받아도 만들지 말고 먼저 확인한다.



\### 만들 것

\- `users` 테이블 + \*\*간단한 회원가입/로그인\*\* (자체 아이디/비밀번호)

\- `todos` 테이블 — \*\*사용자별\*\* (각 할일은 주인이 있다)

\- 할일 CRUD API 5개 — \*\*로그인한 사용자의 할일만\*\* 조회·조작 (인증 필요)

\- 마감 임박 알림: 마감 1시간 전 \& 미완료면 외부 채널로 발송 (\*\*아웃바운드\*\*)



\### 안 만들 것 (3일 범위 밖 — 구현 금지)

\- 구글 캘린더 연동

\- 소셜 로그인(구글/카카오/디스코드 OAuth) — \*\*자체 아이디/비번만\*\* 쓴다

\- 비밀번호 재설정, 이메일 인증, 프로필 등 회원 부가 기능

\- \*\*인바운드 웹훅 / 봇 명령어 수신\*\* — 알림은 우리 서버가 \*\*보내기만\*\* 한다(아웃바운드). 외부가 우리 서버로 POST하는 인바운드는 없다.



\---



\## 3. 기술 스택 (버전 고정)

\- Python 3.11+

\- FastAPI (설치 시점 최신 안정 버전)

\- SQLite — 파일 DB (`app.db`)

\- SQLModel (ORM + 스키마) — \*\*Pydantic v2를 지원하는 버전\*\*

\- \*\*Pydantic v2\*\* — v1 문법 사용 금지

\- 비밀번호 해싱: \*\*bcrypt 계열\*\* (평문 저장 절대 금지)

\- 로그인 토큰: \*\*JWT\*\* (FastAPI 표준 OAuth2 password flow, 최소 구성)

\- APScheduler (알림 스케줄러)

\- `requirements.txt`에 설치한 버전을 고정해 3명 환경을 맞춘다.



\---



\## 4. 인증 (간단하게)

\- \*\*회원가입\*\*: `{username, password}` → 유저 생성. 비밀번호는 \*\*해시해서\*\* 저장.

\- \*\*로그인\*\*: `{username, password}` → 맞으면 \*\*토큰(access\_token) 반환\*\*.

\- \*\*비밀번호 평문 저장·응답 반환 절대 금지.\*\* API 응답에 비밀번호(해시 포함) 넣지 않는다.

\- \*\*보호된 엔드포인트\*\*: 요청 헤더에 `Authorization: Bearer <token>` 필요. 없거나 틀리면 `401`.

\- 할일 API는 전부 보호 대상 — \*\*로그인한 사용자 본인의 할일만\*\* 보이고 조작된다. 남의 `id`에 접근하면 `404`(또는 `403`).

\## 5. 데이터 모델



\### `users`

| 컬럼 | 타입 | 기본값 | 설명 |

|---|---|---|---|

| `id` | int, PK | auto | |

| `username` | str, \*\*unique\*\* | (필수) | 로그인 아이디 |

| `password\_hash` | str | (필수) | 해시된 비밀번호 (평문 금지) |

| `created\_at` | datetime | now | 가입 시각 |



\### `todos`

| 컬럼 | 타입 | 기본값 | 설명 |

|---|---|---|---|

| `id` | int, PK | auto | |

| `user\_id` | int, FK→users.id | (필수) | \*\*이 할일의 주인\*\* |

| `title` | str | (필수) | 할일 제목 |

| `due\_at` | datetime? | null | 마감 시각 (없을 수 있음) |

| `is\_done` | bool | false | 완료 여부 |

| `notified` | bool | false | \*\*알림 발송됨 여부 — 중복 발송 방지용 내부 플래그\*\* |

| `created\_at` | datetime | now | 생성 시각 |



\- `password\_hash`, `user\_id`, `notified`는 \*\*내부 전용\*\* — todo/유저 API 응답에 노출하지 않는다.

\## 6. API 계약 (팀 공용 — 바꾸려면 프론트에 먼저 알림)

> ⚠️ 회원가입 도입으로 계약이 바뀌었다. 기존 `API\_계약서.md`를 \*\*아래 기준으로 갱신해 프론트에 재공유\*\*할 것.



\### 인증

| 엔드포인트 | 요청 body | 성공 응답 |

|---|---|---|

| `POST /auth/register` | `{username, password}` | `201` + 유저 정보(비번 제외) |

| `POST /auth/login` | `{username, password}` | `200` + `{access\_token, token\_type}` |



\### 할일 (전부 `Authorization: Bearer <token>` 필요, 본인 것만)

todo 객체 응답 형태:

```json

{

&#x20; "id": 1,

&#x20; "title": "장보기",

&#x20; "due\_at": "2026-03-10T18:00:00",

&#x20; "is\_done": false,

&#x20; "created\_at": "2026-03-07T09:00:00"

}

```

| 엔드포인트 | 요청 body | 성공 응답 |

|---|---|---|

| `POST /todos` | `{title, due\_at?}` | `201` + todo |

| `GET /todos` | 없음 | `200` + todo 배열 (내 것만) |

| `GET /todos/{id}` | 없음 | `200` + todo |

| `PATCH /todos/{id}` | `{title?, due\_at?, is\_done?}` | `200` + todo |

| `DELETE /todos/{id}` | 없음 | `204` (본문 없음) |



\### 계약 규칙

\- 날짜·시각은 \*\*전부 ISO 8601 문자열\*\* (예: `2026-03-10T18:00:00`).

\- 마감 없음 = `due\_at`: \*\*`null`\*\* (빈 문자열/0 아님).

\- 완료 여부 = \*\*`true`/`false`\*\* (1/0, "Y"/"N" 아님).

\- \*\*완료 토글은 `PATCH`의 `is\_done`으로.\*\* 완료 전용 엔드포인트 만들지 말 것.

\- 인증 실패 `401`, 없는 `id` `404`, 요청 형식 오류 `422`. 본문은 FastAPI 기본 `{"detail": "..."}`.

\## 7. 알림 (채널 미정 — 함수 하나로 추상화)

\- \*\*채널은 아직 안 정해짐 (디스코드 / 텔레그램 후보).\*\* 그러니 발송 부분을 \*\*`send\_notification(text: str)` 함수 하나로 분리\*\*한다. 채널이 정해지면 이 함수 속 구현과 환경변수만 바꾸고, 아래 스케줄러 로직은 \*\*손대지 않는다.\*\*

\- \*\*방향: 아웃바운드 전송만.\*\* 두 후보 다 "우리 서버 → 외부 채널"이다.

&#x20; - 디스코드(가장 간단): 채널 웹훅 URL에 `{"content": "..."}` JSON을 \*\*POST\*\*. 봇/인증 불필요.

&#x20; - 텔레그램: 봇 토큰 + `chat\_id`로 `sendMessage` POST.

\- \*\*스케줄러 (채널과 무관, 고정):\*\* APScheduler로 \*\*5분마다\*\* 실행 →

&#x20; 대상: `is\_done = false` \*\*AND\*\* `notified = false` \*\*AND\*\* `due\_at`이 (지금 \~ 지금+1시간) 범위 →

&#x20; 각 대상에 `send\_notification(...)` 호출 → \*\*성공하면 그 행 `notified = true`로 UPDATE\*\*.

\- ⚠️ \*\*`notified` 확인/갱신 없이 발송하지 마라.\*\* 안 그러면 5분마다 같은 알림이 무한 발송된다.

\- 알림은 \*\*팀 공용 채널 1곳\*\*으로 보낸다(사용자별 채널 아님). 메시지 텍스트에 \*\*누구의 어떤 할일인지\*\*(username + title)를 담는다.

\## 8. 환경 변수 (`.env`)

비밀값을 코드에 하드코딩하지 않는다. `.env`에서 읽고, `.env`는 \*\*커밋 금지\*\*(`.gitignore`).

```

\# 인증

SECRET\_KEY=...            # JWT 서명용 (아무나 못 만들게 긴 랜덤 문자열)



\# 알림 (채널 정해지면 해당 줄만 채움)

NOTIFY\_TARGET=discord     # 또는 telegram

DISCORD\_WEBHOOK\_URL=...   # 디스코드 쓸 때

TELEGRAM\_BOT\_TOKEN=...    # 텔레그램 쓸 때

TELEGRAM\_CHAT\_ID=...      # 텔레그램 쓸 때



\# DB

DATABASE\_URL=sqlite:///app.db

```

\## 9. 작업 규칙 (Claude Code에게)

\- 2번 "절대 범위"를 넘는 기능은 만들지 않는다. 애매하면 \*\*코드보다 질문 먼저.\*\*

\- 한 번에 앱 전체를 쏟아내지 말고, \*\*요청받은 기능 단위로만\*\* 작업한다.

\- 초보 팀이 유지보수한다. 파일을 적절히 나누고, \*\*핵심 로직엔 "왜 이렇게 했는지" 한국어 주석\*\*을 남긴다.

\- \*\*비밀번호·토큰 처리는 표준 라이브러리를 쓰고 직접 발명하지 않는다.\*\* 비번은 해시, 응답에 노출 금지.

\- \*\*Pydantic v1 문법 금지\*\* (`class Config`, `.dict()` ❌ → `model\_config`, `.model\_dump()` ✅).

\- 알림 발송은 반드시 `send\_notification()` 안에만 둔다. 스케줄러/CRUD 코드에 채널별 코드를 흩뿌리지 않는다.

\- 모든 설명·주석은 한국어로.

```bash
pip install -r requirements.txt

uvicorn main:app --reload

```
